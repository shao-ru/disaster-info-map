# 避難所の調査と写真

避難所ごとに「だれが使えるか」「どの災害のときに使えるか」を調べて記録し、写真も集めます。
集めた情報は、地図の「条件」（例：洪水・高齢者）で絞り込むときや、避難所の吹き出しに使われます。

---

## 1. 記録する項目と値

### 書く値（すべての項目で共通）

| 書く値 | 意味 | 例 |
|---|---|---|
| `可` | 使える・受け入れる | |
| `条件付き` | 条件つきで使える | 洪水のときは 2 階以上に避難する |
| `不可` | 使えない・受け入れない | 洪水のときは使えない |
| （空） | 不明（まだ分からない） | **分からないときは、何も書かない** |

**「不明」と「不可」は別のもの** です。調べて分からなかったときは、空のままにします。

空の項目は、国土地理院のデータからの自動の推定（なければ不明）がそのまま使われます。
自動の推定がまちがっていて、正しい値も分からないときだけ、`不明` と書くと推定を消せます。

### 項目（列の名前）

| 列の名前 | 書くこと |
|---|---|
| `利用条件` | `可` だれでも利用できる　`条件付き` 対象者だけ（例：施設利用者とその家族）　`不可` 直接は行けない（市が開設を知らせてから行く二次避難所など） |
| `利用条件の説明` | `利用条件` が `条件付き` や `不可` のときの条件（例：施設利用者とその家族） |
| `高齢者` `障害者` `乳幼児・妊産婦` | 受け入れるか |
| `福祉避難所` | 福祉避難所なら `可`、ちがうなら `不可` |
| `ペット` | ペットと一緒に避難できるか |
| `洪水` `崖崩れ、土石流及び地滑り` `高潮` `地震` `津波` `大規模な火事` `内水氾濫` `火山現象` | その災害のときに使えるか（列名と順番は、国土地理院の指定緊急避難場所データと同じ） |
| `根拠` | **必ず書く**。調べたページの URL や資料名 |
| `調査者` | GitHub のユーザー名 |
| `memo` | 自由に（アプリには出ません） |

`id`・`name`・`住所` は最初から入っています（書き換えません）。

### 値が決まる順番

アプリに出る値は、次の順に決まります。

1. **調査**：このあと説明する `attrs` のファイルに書いた値（吹き出しで **太字の枠** になる）
2. **自動**：国土地理院のデータから推定した値
   - 指定緊急避難場所の「洪水」「地震」などの指定
   - 「受入対象者」「備考」の文字（例：「洪水時使用不可」→ 洪水 0、「要配慮者」→ 対象者のみ・福祉避難所）
3. どちらにもなければ **不明**

調べた項目だけを書けば、ほかの項目は自動の値（または不明）のままになります。

## 2. 調べて記録する

### 2.1 調べる

市のホームページで、次のような資料を探します（柏市の例）。

- 指定避難所・指定緊急避難場所の一覧
- 福祉避難所の一覧（どんな人が対象か、直接行けるか）
- ペット同行避難の説明（どの避難所でペットと一緒に避難できるか）
- 洪水ハザードマップ（浸水するとき、何階以上に避難するか）

資料に書いていないことは、推測で書かずに空（不明）にしておきます。

### 2.2 記録する

市区町村ごとのファイル `data/static/shelters/attrs/<市区町村コード>.csv` に書きます（柏市は `12217.csv`）。
全部の避難所の行があり、`id`・`name`・`住所` が入っています。調べた避難所の行に、値を書き込みます。

```
id,name,住所,利用条件,利用条件の説明,高齢者,障害者,乳幼児・妊産婦,福祉避難所,ペット,洪水,崖崩れ、土石流及び地滑り,高潮,地震,津波,大規模な火事,内水氾濫,火山現象,根拠,調査者,memo
E1221700001111,柏市立柏第一小学校,千葉県柏市あけぼの1-7-6,可,,,,,,不可,条件付き,,,,,,,,https://www.city.kashiwa.lg.jp/xxxx,taro,
```

↑ 柏第一小学校は「だれでも利用できる（利用条件 可）」「ペットは不可」「洪水は条件付き」という例です。書いていない項目は不明（または自動の推定）のままです。

- **VS Code で編集** します（拡張機能「Rainbow CSV」を入れると、列が色分けされて見やすくなります）。**Excel は使いません**（保存すると、ファイル全体の書き方が変わってしまうため）
- 1 つの施設は 1 行。行の順番は変えない
- ほかの人が担当する行は書き換えない
- 施設の ID は、地図で施設をクリックしたときの吹き出しの一番下に出ています

### 2.3 確かめる

```
uv run ./code/build_shelters.py
```

- 書き方がおかしいと、どのファイルの何行目かが出ます（何も書き換えずに止まります）
- うまくいくと、最後に「調査の結果（attrs/）：○ 施設」と出ます
- アプリ（`uv run ./code/serve.py`）で施設をクリックし、書いた値が **太字の枠** で出ていれば OK です

### 2.4 Pull Request を出す

`attrs/<コード>.csv` と、作り直された `data/static/shelters/*.geojson`・`regions.json` を一緒にコミットします。
PR を出すと自動でチェックが動き、CSV と GeoJSON が合っていないと ❌ になります（`build_shelters.py` を実行し忘れたとき）。

### 2.5 ほかの市区町村を追加する

```
uv run ./code/make_attrs_template.py 12220     … 流山市（12220）のファイルを作る
```

市区町村コードは `data/static/regions.json` で調べられます。すでにファイルがあるときは、足りない施設の行だけが追加されます。

### 2.6（★★★）自動の推定を改善する

自動の推定ルールは `code/shelter_attrs.py` の `auto_attrs()` にあります。
全国の「備考」には、まだ読み取れていない書き方がたくさんあります（例：「1階は浸水のおそれ」）。
ルールを直したら `build_shelters.py` を実行し、最後に出る「項目ごとの件数」がどう変わったかを PR に書いてください。

## 3. 写真を登録する

### 3.1 撮るときの約束

- 人の顔や車のナンバーが写らないようにする（写ったら使わない）
- 建物の入口・看板など、その避難所だと分かるものを撮る
- 私有地や立入禁止の場所には入らない

### 3.2 登録する（パソコンで）

1. 写真をパソコンに移す（iPhone の HEIC は、写真アプリで JPEG に書き出しておく）
2. `uv run ./code/serve.py` でアプリを開く
3. 地図で避難所をクリック → 吹き出しの **「📷 写真を追加」**
4. 写真を選び、撮影日・GitHub のユーザー名・メモ（どこから撮ったか）を入れて **「保存」**
   - 撮影日は写真から自動で入ります
   - 撮影した場所が避難所から 300 m 以上離れていると注意が出ます（別の避難所の写真でないか確かめる）
   - 写真は自動で小さくし（長い辺 1600 px）、撮影場所などの記録を消してから保存されます
5. 吹き出しに写真が出れば OK です

保存先は `data/static/photos/` で、写真と説明が 1 組になっています。

```
E1221700001111_taro_01.jpg     写真
E1221700001111_taro_01.json    説明（撮影日・撮影者・メモ）
```

「写真を追加」は、手元で `serve.py` を動かしているときだけ出ます（公開中のサイトには出ません）。

### 3.3 Pull Request を出す

`data/static/photos/` の **写真（.jpg）と説明（.json）の両方** をコミットします。
写真の一覧（`index.json`）は自動で作られるので、コミットしません。

チェックだけしたいとき：

```
uv run ./code/build_photos.py
```
